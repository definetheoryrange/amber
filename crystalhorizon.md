# Fajia ScoreHub

Fajia ScoreHub is a specialized technical resource aggregation and data indexing platform designed for researchers, data analysts, and policy observers who require structured access to competitive ranking and scoring datasets within the Chinese public evaluation domain. The project addresses the growing need for a centralized, machine-readable repository of official competition results, technical score breakdowns, and performance benchmarking records that are currently scattered across multiple authoritative but siloed publication channels.

Targeting users who work with public performance metrics, educational assessment data, or institutional ranking systems, Fajia ScoreHub provides a unified query interface, normalized data schemas, and version-controlled historical snapshots. The platform does not host original data but acts as a meticulously curated navigation hub that maps each data source to its original publication endpoint, preserving the integrity and timeliness of the underlying information while offering enhanced discoverability and cross-reference capabilities.

## 功能概览

- **Unified Resource Indexing** – Aggregates official result and score announcement portals under a single, well-structured navigation system, eliminating the need for manual search across multiple government-affiliated domains.

- **Live Data Source Monitoring** – Implements a lightweight polling mechanism that checks each registered URL for content updates and generates change logs for downstream consumers.

- **Normalized Metadata Extraction** – Parses HTML meta tags and structured data patterns from each target URL to extract publication date, document title, and category classification.

- **Batch Query Interface** – Provides a RESTful API endpoint that accepts lists of source codes and returns aggregated metadata in JSON format for programmatic access.

- **Historical Snapshot Archiving** – Stores daily snapshots of each source's availability status and response header information, enabling trend analysis and outage detection.

- **Categorized Browsing Tree** – Organizes all indexed URLs into logical categories (e.g., competition results, technical scoring, ranking networks) with faceted filtering.

- **Search-As-You-Type Lookup** – Offers a client-side fuzzy search against the indexed resource titles and descriptions, with instant result filtering.

- **Exportable Source Manifest** – Generates plain-text and CSV manifests of all tracked URLs with their last-verified timestamps for offline auditing.

## 应用场景

- **Policy Research Data Curation** – Researchers studying regional competition outcomes can use the platform to maintain a dynamic bibliography of official result publications. Instead of bookmarking each domain individually, they rely on the unified index to access all relevant score announcement pages within seconds.

- **Educational Performance Benchmarking** – Analysts comparing technical score distributions across multiple cohorts leverage the platform's normalized metadata to quickly identify which source contains the desired scoring period. The batch query feature allows them to retrieve headers and timestamps from all sources simultaneously.

- **Institutional Reporting Automation** – Organizations that need to include official score citations in their periodic reports utilize the monitoring feed to detect new publications. The change log generated by the platform reduces manual re-verification efforts and ensures that citations reference the most current version.

- **Data Quality Assurance Auditing** – Quality engineers testing data pipeline reliability use the snapshot archive to verify that each source endpoint remains accessible and returns expected content types over time. The historical availability data helps distinguish transient network issues from permanent endpoint changes.

- **Open Data Portal Supplementation** – Civic tech projects that build public dashboards on competition statistics integrate the platform's metadata API to populate source attribution fields, ensuring compliance with data origin disclosure requirements.

## 快速开始

```bash
# Step 1: Clone the repository
git clone https://github.com/fajia-scorehub/fajia-scorehub.git
cd fajia-scorehub

# Step 2: Install dependencies using pipenv (recommended) or pip
pip install -r requirements.txt
# Alternatively, if using pipenv:
# pipenv install --dev

# Step 3: Initialize the local metadata database and run the development server
python manage.py migrate
python manage.py load_initial_sources
python manage.py runserver --host 0.0.0.0 --port 8080
```

After the server starts, navigate to `http://localhost:8080/status` to verify that all initially configured source URLs are reachable. The first full polling cycle runs automatically within 30 seconds of startup.

## 常见问题

**轮询检测是否会触发目标网站的访问限制或反爬机制？**

平台默认将轮询频率设置为每 24 小时一次，且每个请求均携带标准的 User-Agent 头（包含项目标识和联系方式）。我们明确禁止任何形式的并发高频率请求或模拟浏览器行为。所有轮询均采用被动 HEAD 方法优先，仅在 HEAD 不可用时降级为 GET 并仅读取前 64KB 响应体。若您作为目标网站管理员希望将特定源从轮询列表中移除，请联系我们并提交正式申请。

**如何确保已收录 URL 的长期可用性和准确性？**

平台维护一个手动审核的静态清单，而非自动爬虫发现的动态列表。每个新增源均需经过核心团队的人工验证，确认其内容主题与类别描述一致。系统每日记录每个源的 HTTP 状态码、响应时间和内容长度摘要。当某个源连续 7 天返回 5xx 或 404 状态时，系统会在仪表板标记“待审查”状态，并通知维护列表进行人工复核。

**能否在私有网络环境中部署该平台？**

可以。整个项目采用纯开源技术栈，无任何外部云服务依赖（除可选的公共 PyPI 索引外）。您可以将整个代码库连同 PostgreSQL 和 Redis 组件部署在完全隔离的内网环境中。所有 URL 源在初始化时通过环境变量或本地 JSON 文件导入，无需访问公网即可运行核心调度和查询功能。
